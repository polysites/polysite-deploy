# Polysite deploy

Ways to run [Polysite](https://github.com/polysites/polysite) beyond the reference setup: Kubernetes, your own reverse proxy, a single VM, bare metal,
and ready-to-copy Docker Compose stacks.

The **reference deployment** (Docker Compose on one server behind Caddy, the deploy script with its rollback, and the backup tool) lives with the code in
the [`polysite`](https://github.com/polysites/polysite) repository. Everything here is an alternative, with its limits written down honestly on its page in the
[deployment guide](https://github.com/polysites/polysite/blob/main/docs/guide/deploy/index.md).

Everything runs in containers: no Node, Helm, kubectl or Terraform on your machine. "Tested" below means run for real; "static" means linted or validated
without running the thing.

## What is here

| Folder | What it is | How it is tested |
| --- | --- | --- |
| `kubernetes/helm/polysite` | The Helm chart: cms, web, edge proxy, migration hook Job, Ingress, optional demo PostgreSQL, Redis, backup CronJob, NetworkPolicy. Published as `oci://ghcr.io/polysites/charts/polysite` | **Static:** `helm lint --strict`, `helm template \| kubeconform` for three value sets, refusal checks. **Tested** on a throwaway k3s: install, hook Job, hardened pods, smoke and proxy checks through an Ingress, upgrade, rollback, backup job, NetworkPolicy, two web replicas |
| `kubernetes/derived-image` | Build your own images with plugins and themes | Documented; the script assembles the build context for the core's Dockerfiles |
| `proxy/` | The Caddyfile's routing, limits and headers for **nginx, Apache and Traefik**, as ready-to-use configs and Compose overrides | **Tested:** each proxy in front of the real stack (whole smoke test plus `checks.mjs`), plain and HTTPS with a self-signed certificate. `docker-compose.hostproxy.yml` is static only |
| `templates/compose-caddy`, `-nginx`, `-apache`, `-traefik` | Self-contained Compose setups: compose file, `init.sh`, README, Dependabot and Renovate configuration, a validate workflow | **Static:** compose validity, pinned images, the proxy copies equal the tested files. **Tested:** the Caddy, nginx and Apache stacks start from images and pass the smoke test. Traefik: static only |
| `templates/kubernetes-helm` | Values, secret script, Argo CD, Flux and kustomize examples | **Static:** values render against the chart; the Argo CD, Flux and kustomize files parse only |
| `templates/vm-cloud-init` | `cloud-init.yaml` (generated by `build.sh`), AWS EC2 Terraform | **Static/partial:** cloud-init schema, shellcheck, files on a clean Ubuntu 24.04, Docker key fingerprint and apt repository; `terraform validate`. Never run on a VM, never applied |
| `templates/bare-metal` | systemd units, env file, build and install scripts, proxy snippets | **Tested** in containers without systemd: both apps built on Node 24 and run with the units' commands behind nginx; smoke test passes. `install.sh` and the units under systemd not run |

## Running the tests

The tests that start a real Polysite need a checkout of the core, for its compose file, `Caddyfile` and smoke test. Clone it next to this repository, or say where it is:

```bash
export POLYSITE_CORE=../polysite     # the default
```

| Command | What it does |
| --- | --- |
| `sh kubernetes/test/lint.sh` | Static checks of the chart. No cluster, no core checkout |
| `sh templates/test.sh static` | Static checks of every template. No images, no core checkout |
| `CMS_IMAGE=... WEB_IMAGE=... BACKUP_IMAGE=... sh templates/test.sh run caddy` | Starts a template's stack from local images and runs the smoke test through it (`caddy`, `nginx` or `apache`) |
| `sh proxy/test/run.sh all` | Each proxy in front of the real stack (or one of `nginx`, `nginx-tls`, `apache`, `apache-tls`, `traefik`, `traefik-tls`, `traefik-labels`). Set `CMS_IMAGE`, `WEB_IMAGE` and `BACKUP_IMAGE` to skip the image build |
| `CMS_IMAGE=... WEB_IMAGE=... BACKUP_IMAGE=... sh kubernetes/test/run.sh` | The chart on a throwaway k3s. Images are named `<registry>/polysite-cms:<tag>` and so on |
| `sh templates/vm-cloud-init/test.sh` | The cloud-init file |
| `sh templates/bare-metal/test.sh <core checkout>` | Both apps built and run without containers |

## Versions

The chart's version is the Polysite version it deploys. Tag this repository `vX.Y.Z` after Polysite `vX.Y.Z` has been released and its images have passed their
smoke test: the `publish-chart` workflow then lints the chart and pushes it to `oci://ghcr.io/polysites/charts`. The templates pin image versions (they say
`v0.1.0` until the first release); bump them after the release.
